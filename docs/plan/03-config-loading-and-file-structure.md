# 03 — Config Loading and File Structure

## 3.1 Where the config lives

- Primary: `$XDG_CONFIG_HOME/hypr/hyprland.lua` → normally `~/.config/hypr/hyprland.lua`
- Override at launch: `Hyprland --config /path/to/hyprland.lua` (or `-c`).
- No config at all → Hyprland generates an example config (with a yellow "autogenerated" warning
  that you remove by deleting `hl.config({ autogenerated = true })`).
- Example config upstream: `example/hyprland.lua` in the Hyprland repo. Installed copy:
  `/usr/share/hypr/hyprland.lua` on Arch.
- **Precedence check happens once at startup.** If you boot with a `.conf` and add a `hyprland.lua`
  mid-session, reload does NOT switch formats until restart (and vice-versa).

## 3.2 Reload semantics

- The config **reloads the moment you save** it (unless `misc.disable_autoreload` is set).
- `hyprctl reload` forces a reload.
- `hyprctl config full-reload` (0.56+) = ground-up reload, discarding applied-but-overridden state.

## 3.3 The `hl` global

Every Lua file you `require()` shares the **same `hl` global** — but each `require()`'d file is
evaluated in its own scope, so locals do not leak between files (unless you return them).

## 3.4 Multi-file configs — `require()` replaces `source =`

```lua
-- ~/.config/hypr/hyprland.lua
require("keybinds")                    -- ~/.config/hypr/keybinds.lua
require("UserConfigs/UserSettings")    -- nested path with /
require("UserConfigs.UserSettings")    -- same, with . separator (portable)
require("./stuff/*")                   -- wildcard include
require("/usr/share/among/us.lua")     -- absolute
```

Rules of thumb:

1. **Relative paths are relative to the `hyprland.lua` directory**, not the current file.
2. `/` is UNIX-specific; `.` works everywhere — prefer `.`.
3. Each `require()` is a **separate protected scope**: a runtime error in `keybinds.lua` does not
   stop `animations.lua` from loading. (Errors in the *main* file still kill the main file.)
4. Missing modules throw a hard error in the calling file — wrap with `pcall` if optional.
5. `require = __require` restores raw Lua behavior (for third-party modules that break under
   Hyprland's scoping).
6. Wildcard `require("./*.lua")` loads in alphabetical order — a cheap way to keep sections sorted.

> HyprFlux migration note: `hyprland.conf` currently `source=`s 15 files. The Lua equivalent is a
> `hyprland.lua` that `require()`s the converted modules. Keep the same `configs/` + `UserConfigs/`
> split (see doc 15).

## 3.5 Error behavior (what breaks, what survives)

| Failure type | Behavior |
|---|---|
| Fundamental syntax error | Config **refuses to reload**, error popup |
| Runtime error mid-file (e.g. call a `nil`) | Execution of that file aborts, error popup; other `require`d files still load |
| Type error in `hl.*` (string where float expected) | Execution continues, error popup |
| Error inside async callback (keybind function) | Notification popup, desktop keeps running |
| Infinite loop / runaway script | Hyprland kills the script after a timeout |

**Emergency safety net:** if a major error happens before your binds load, Hyprland injects
emergency binds **SUPER+Q / SUPER+R / SUPER+M** (terminal, run, exit) and says so in the error
popup.

## 3.6 Validation without booting

```bash
Hyprland --verify-config    # parses+applies config headlessly; exit code + errors
luac -p hyprland.lua        # pure Lua syntax check (catches syntax, not API misuse)
hyprctl verify-config       # same as --verify-config at runtime
```

> 0.55.0's `--verify-config` segfaulted (fixed in 0.55.1) — you're on 0.56.2, fine.

## 3.7 The REPL and `hyprctl eval`

```bash
hyprctl repl                # interactive Lua REPL against the running compositor
hyprctl eval 'hl.unbind("SUPER + O")'
hyprctl eval 'hl.dispatch(hl.dsp.submap("reset"))'
hyprctl eval 'local w = hl.get_active_window(); if w then print(w.title) end'
```

`hyprctl eval` executes Lua *in the compositor*, so it can call `hl.*` and read live state —
this is the new replacement for `hyprctl keyword` + socket2 scraping, and it's the best way to
prototype a snippet before putting it in the config.

## 3.8 LSP / editor autocompletion

Hyprland ships generated Lua stubs in `/usr/share/hypr/stubs/hl.meta.lua` (installed — verified
on this machine). Wire them into your LSP:

```json
// .luarc.json (repo root, for any LSP)
{ "workspace": { "library": ["/usr/share/hypr/stubs"] } }
```

```json
// .vscode/settings.json
{ "Lua.workspace.library": ["/usr/share/hypr/stubs"] }
```

With LuaLS (sumneko) you get full autocomplete + signature help for every `hl.*` function — the
single biggest quality-of-life upgrade of this migration.

## 3.9 Suggested target layout for HyprFlux

```
~/.config/hypr/
├── hyprland.lua              # bootstrap: requires everything (replaces hyprland.conf)
├── monitors.lua              # nwg-displays generated (replaces monitors.conf)
├── workspaces.lua            # nwg-displays generated (replaces workspaces.conf)
├── hyprflux-colors.lua       # color module, returns a table (replaces hyprflux-colors.conf)
├── configs/
│   └── keybinds.lua          # default keybinds (replaces configs/Keybinds.conf)
├── UserConfigs/
│   ├── 00-Readme
│   ├── startup-apps.lua      # hl.on("hyprland.start", ...)
│   ├── env-variables.lua     # hl.env(...)
│   ├── laptops.lua           # device binds + hl.device
│   ├── window-rules.lua      # hl.window_rule / hl.layer_rule
│   ├── user-decorations.lua  # hl.config decoration/general
│   ├── user-animations.lua   # hl.curve + hl.animation
│   ├── user-keybinds.lua
│   ├── user-settings.lua
│   └── user-defaults.lua     # locals (term, files, search engine...)
├── Monitor_Profiles/         # unchanged (profiles), but new ones saved as .lua
├── animations/*.lua          # preset modules (converted from *.conf)
└── (hyprlock.conf, hypridle.conf, application-style.conf stay hyprlang!)
```
